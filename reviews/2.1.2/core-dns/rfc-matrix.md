# RFC conformance matrix: DNS wire core

Target reviewed: `EvotecIT/DnsClientX` commit `1cfb438fd4c75a8ae54d457fb3073ab4aeb3718a` (tag `DnsClientX-v2.1.2`). This is a client-library review. Server-only obligations are identified separately and are not reported as client defects.

| RFC area | Applicable client requirement | Implementation and evidence | Assessment |
|---|---|---|---|
| RFC 1035 §§4.1.1–4.1.2: header, flags, sections, labels | Emit/parse the 12-octet header and honor section counts, label lengths, and message boundaries. | `DnsMessage.SerializeDnsWireFormat`; `DnsWire.ParseMessage`; bounded `DnsWireReader`. The full suite includes short-header, impossible-count, trailing-data and reserved-label cases. | Mostly compliant. `TryParseEdns` has a separate 50-label cap that rejects some otherwise valid names (F-03). |
| RFC 1035 §4.1.4: name compression | Decode compression pointers as offsets to prior occurrences; enforce valid expanded-name bounds and avoid loops. | `DnsWireReader.ReadName` rejects forward offsets and expanded names above 255 octets. Constructed response tests show a pointer to DNS ID byte 0 is accepted as root, and a backward-only 129-pointer chain is rejected as a loop (F-04, F-05). | Partial. |
| RFC 1035 §4.1.1: transaction ID and response bit; request/response Question matching | Correlate a response with the outstanding transaction and expected Question. | `DnsWire.ParseMessage` checks QR, transaction ID, opcode, one Question, canonical name, type, and class. Existing `DnsWireResponseValidationTests` reject wrong ID and QR=0; full suite passed. | Compliant for the reviewed ordinary query path. |
| RFC 1035 §4.2.1 and RFC 5452 response matching | Accept a datagram only from the resolver endpoint contacted for that query. | Non-pooled UDP calls `UdpClient.Connect`; pooled sockets are also connected when created. A local two-socket probe sent a matching-ID and Question response from a different source port; the client ignored it and timed out. | Compliant in the tested .NET/Linux path. |
| RFC 7766: TCP support and TC retry guidance | Support DNS over TCP and use it to complete a truncated UDP exchange when configured. | `Configuration.UseTcpFallback` defaults to `true`; `DnsWireResolveUdp` checks TC and invokes TCP. `DnsWireFallbackTests.ResolveWireFormatUdp_ShouldFallbackToTcpWhenTruncated` passed. The option can intentionally disable fallback. | Compliant in the default configuration. A response that is itself malformed is rejected before the TC branch is reached. |
| RFC 1035 §4.2.2: TCP framing | Prefix each DNS message with its two-octet big-endian length; the DNS body must fit the 16-bit length. | Direct TCP and pooled TCP/DoT emit the prefix and read the declared body exactly. One-byte short-read and early-close probes confirmed `ReadExactAsync` loops and reports EOF. A 65,564-octet serialized query is not rejected and its prefix wraps to 28 (F-01). | Partial. |
| RFC 7766: TCP use and connection management | TCP support is available; persistent streams must preserve message framing and correlate replies to outstanding IDs. | Direct TCP is supported. The pool serializes writes, reserves IDs, demultiplexes framed replies, and retires failed streams. Full tests for sequential reuse, pipelining, cancellation, timeout, late replies and disposal passed. | Compliant in tested paths, subject to F-01 for overlength queries. |
| RFC 6891 §§6.1.2–6.1.3: OPT and extended RCODE/version | Put at most one OPT pseudo-RR in Additional, encode root owner and payload size, and combine the extended RCODE with the header RCODE. | Query encoder emits one OPT with version 0 and configured UDP size. Response parser rejects duplicate or non-Additional OPT, checks decoded root owner, extracts UDP size/version/flags and combines extended RCODE. `ExtendedRcodeAndEdeAreParsedFromOpt` passed. | Mostly compliant. The total query length is not bounded by the TCP framing width (F-01). |
| RFC 6891 §6.2: advertised UDP payload size | Carry the requestor's receive size in OPT CLASS; the client chooses and reports the value it supports. | `DnsMessage` restricts configured EDNS size to 512–65,535; the response API exposes the received class. The parser test exercised 1,232 octets. | Compliant for values tested. No separate stress test exercised large UDP datagrams. |
| RFC 7871 §6.1: EDNS Client Subnet | Encode a family-appropriate source prefix (IPv4 0–32, IPv6 0–128) and the corresponding address bytes; query scope is zero. | `EcsOption.GetData` truncates/masks address bytes and writes scope 0, but does not reject a prefix above the family's address width. `/33` for IPv4 serialized with source prefix 33 (F-02). | Partial. |
| RFC 7830 / RFC 7873 / RFC 8914: padding, COOKIE, EDE | Respect option code/length boundaries and the option-specific response format. | `ParseEdnsOptions` bounds each option to OPT RDATA; response COOKIE length is checked and EDE requires its two-octet code. Unknown options are retained as opaque OPT RDATA rather than treated as DNS records. EDE parsing was covered by the full suite. | Compliant for inspected option paths; no exhaustive option fuzzing was performed. |
| RFC 2181 §8: received TTL high bit | Treat a TTL with the high bit set as zero. | `DnsWire.ReadRecords` maps values greater than `int.MaxValue` to zero. | Compliant by inspection. |

## Role boundary: client versus server

The review assesses what this client sends, parses, correlates, and accepts. It does not treat the following server responsibilities as client findings: returning BADVERS when the server does not support an EDNS version, selecting response size within the requestor's advertised receive limit, setting TC when it cannot fit a complete UDP response, or providing authoritative ECS policy. The client does parse and expose the returned EDNS version and extended RCODE.

## Finding index

- **F-01**: The serializer permits a DNS body above 65,535 octets; TCP frame construction truncates its length to 16 bits.
- **F-02**: The ECS query encoder serializes source prefixes outside the address family's valid range.
- **F-03**: The lightweight EDNS parser rejects valid names with more than 50 labels.
- **F-04**: The full parser accepts a compression pointer into the DNS header as a domain name.
- **F-05**: The full parser rejects a finite, backward-only compression chain after 128 pointer hops.
